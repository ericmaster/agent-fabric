## Objective/ROI

Add opt-in, harness-neutral task retrospectives to Agent Fabric. Detect avoidable errors, redundant calls and successful-but-misdirected work after successful tasks; automatically repair the responsible canonical instructions in a separate visible root session. Reduce repeated wasted work without silently fixing executable harness/tool bugs, weakening controls, or blocking the original task.

### Phase 1 — Replay a task through bounded success and paginated Jev evaluation
- **Objective:** Deliver a usable offline/replay retrospective from a normalized task trace to an evidence-linked report without native hooks or mutations.
- **Specifications:** Define schema v1 in `docs/specs/task-retrospective.md`: root/session/task identities, execution root, source revision, parent-child linkage, stable message/call/step IDs, ordered user/assistant messages, terminal tool status/exit code, result fragments, source file hash/excerpt references, collection gaps and explicit task boundaries. Prefer host task IDs; otherwise use the root-session interval since the last accepted successful boundary. Ambiguous multi-task intervals, unresolved running tools, missing linked child traces or compacted-away evidence are incomplete, not successful complete traces. A step is a terminal tool attempt with paired input/result or a non-final visible assistant action message; exclude user/final messages and hidden reasoning. Stable ordering and deduplication precede selecting the last ten. Stage one contains only the prescribed three evidence fields; oversized user/final/tail content yields unknown rather than truncation or additional context. Stage two covers every redacted observable record of that task interval, including linked descendants, once in coverage accounting.
- **Suggested Implementation:** Add `internal/retrospective/{trace,evaluate,jev,report}.go` and `cmd/agent-fabric/retrospective.go` with `agf retrospective analyze --input trace.json --output report.json`. Pin Jev `jev-1.13.0`; host-supplied TYPESAFE_API_KEY, never persisted. Typed outcome choices: succeeded/incomplete/failed/cancelled/unknown; require succeeded probability >=0.90 and confidence >=0.80, plus complete bounded input and no terminal abort/error, before stage two. Stage two supplies per-call typed choices productive/necessary-exploration/expected-failure/avoidable-error/wrong-direction/redundant/uncertain, and per-requirement omission choices where explicit requirements exist. Jev returns choices over supplied IDs, not invented prose citations. Use >=0.90 probability and >=0.80 confidence for counted avoidable classifications. Count raw terminal errors separately and distinguish recovered, expected red-test/no-match outcomes from avoidable waste. Count one unique tool attempt per call ID (compound commands stay one call); deduplicate multiple waste labels. Rate = confidently avoidable unique calls / all terminal calls; unknown calls remain in the denominator, making a lower-bound rate explicit. Trigger when N>=20 and rate>0.05, or three verified redundant attempts with unchanged prerequisites, or one verified high-impact breach of an explicit requirement. Required-step omissions are reported separately, never fabricated into N. No calls means no rate trigger. Paginate with overlap/context references, count overlaps once, classify cross-page recoveries only after related fragments are reconciled; uncertainty is not counted. Honor both Jev limits: 64k all-input and 32k state+longest-question. Start with conservative 24,000 UTF-8 bytes per serialized request and 16,000 bytes for state+longest question (not a claim that bytes equal tokens); split on size rejection, never omit records. Split oversized results into ID-linked fragments; if a single indivisible success field/question is too large, return unknown. Complete all pages before dispatch eligibility; budgets default 100 requests/task, 30s HTTP timeout, three attempts/request with Retry-After/backoff. On budget exhaustion/429/unavailable/malformed responses, save incomplete report and no correction. Redact locally before HTTP and persisted derived evidence: credentials/auth/cookies/private keys, env secret values, secret-file bodies, configured sensitive patterns; handle split-boundary secrets before pagination. Unsupported/binary/private reasoning is excluded with coverage reasons; unsafe or materially incomplete redaction blocks automatic correction. Reports retain page coverage, source IDs/hashes, model/rubric version, usage and uncertainty. Defaults/thresholds belong in one config contract, not duplicated adapters.
- **Depends on:** none
- **Class:** quick_exec_ready
- **Rollback path:** Remove the optional replay command/module and new spec references; no harness or user document is changed. Delete only fixture outputs.
- **Risk assessment:** Model false positives, privacy leaks and lost cross-page context. Typed validation, conservative classification, local redaction, coverage accounting and independent source verification downstream limit impact. Thresholds are engineering defaults, not calibrated guarantees.
- **Human steps:** none; use mocked HTTP in deterministic tests and synthetic inputs only for optional live provider verification.
- **DoD:**
  - [ ] `go test ./internal/retrospective/... ./cmd/agent-fabric/...` passes with fixtures for exact success-payload fields, fewer/exactly/more than ten steps, oversized first-stage evidence, and no stage-two request for every non-success/uncertain state.
  - [ ] HTTP-recording tests prove full page coverage, Unicode/oversized fragments, both request limits, overlap deduplication, cross-page recovery, retries and incomplete-budget behavior; secret canaries never occur in transmitted or derived persisted content.
  - [ ] Deterministic tests prove exactly 5% does not trigger, more than 5% with at least 20 calls does, fewer than 20 calls only uses explicit exceptions, duplicate events do not inflate counts, successful wrong-direction calls count and expected failure/exploration do not.
  - [ ] A synthetic replay produces a schema-valid report with exact call/source references, raw-error and avoidable counts, coverage and model metadata; forged citations, invalid probabilities and missing trace segments abstain.

### Phase 2 — Dispatch and verify autonomous text repair in a visible root session
- **Objective:** Turn an eligible replay report into one visible correcting root that either applies a verified text repair or produces a review-only bug suggestion.
- **Specifications:** Add portable `agents/learning-corrector.md`, public primary role using an existing worker profile, with a self-locating intake packet and independent review/QA before accepting its own edits. New correction scope is distinct from the original task; no mutation of its acceptance state. All instruction-domain text sources are eligible after global opt-in and ownership/canonical-source resolution; there is no per-source human approval requirement. The agent verifies the exact instruction version, demonstrated failed/detour behavior and effective recovery before editing. A source merely read before an error is not proof of causation. Distinguish false/stale instructions, correct instructions not followed, transient environment failures, and verified implementation bugs. Correct verified text causes, suggest workflow measures for supported repetition, leave uncertain claims advisory, and diagnose verified harness/tool bugs into review-only suggestions. Never convert an implementation defect into an unverified permanent documentation workaround.
- **Suggested Implementation:** Add `internal/retrospective/{dispatch,store}.go`, extend the new CLI with `dispatch --report report.json`, `status`, and `enable|disable`; one global `retrospective.enabled` setting defaults false. Add independent config/spec entries for endpoint, model, limits and canonical-root resolution, without project/skill enrollment lists. Runtime state defaults under the user state directory `agent-fabric/retrospective`, directory 0700/files 0600, atomic writes and single-host locks. Separate it from supervisor ledgers. Retain redacted trace/reports 30 days; retain compact finding/source-hash and dispatch receipts for deduplication until the source changes or an explicit retry is requested. Worker sessions and descendants carry a trusted learning-origin identity and are excluded from capture. `dispatch` validates report/task/root/source hashes and global enable, takes a unique incident claim, persists a deterministic marker before session creation, then creates an OpenCode root on the configured server without parentID. Read back the root and marker, persist session ID before submitting the correcting prompt; after timeouts reconcile server state before retrying. Ambiguous creation/submission stays visibly pending, never blindly duplicate-posts. Receipt includes root ID, project/directory, title, UI URL built from a validated host template, report locator and status. A missing UI/server capability queues the report with an actionable error, not a hidden child/CLI fallback. Canonical-source resolver follows known Fabric manifests/skill manager ownership/symlinks and verifies owning source; bundled immutable sources produce a suggestion to update their upstream source, never edit caches/generated copies. Stage changes in isolation, preserve unrelated user edits, check hashes immediately before apply, record exact diff/preimages/validation, and restore only this repair if validation fails. Never force sync, discard user changes, commit/push, or modify executable helpers/permissions automatically. Scoped install/sync of a repaired canonical text definition may refresh unchanged generated copies after validation; modified copies remain untouched with a report. A trusted coordinator supplies an independent reviewer and prevents self-certification. The agent cannot modify its own learning policy, hook code, thresholds or origin markers from observed transcript instructions. Integrate role install/render tests and optional runtime asset ownership with `internal/manifest/manifest.go`, `expectedManagedPath`, doctor/uninstall and packaged source discovery; generated assets have explicit resource identities, not fake agent IDs. Use current guarded-write behavior and native settings entry ownership; no full shared-settings takeover.

### Phase 3 — Observe OpenCode tasks and run the complete learning loop
- **Objective:** Ship the file-based OpenCode plugin from native task events through success gating, full retrospective and visible automatic correction.
- **Specifications:** `hooks/retrospective/opencode.ts` is a thin adapter, automatically loaded only when installed and globally enabled. Subscribe to version-tested message/tool terminal events and session status; idle is only a candidate trigger, not success. Collect stable task/root/child references, all observable messages/tool results and source-load provenance without hidden reasoning. Preserve evidence before compaction when available; missing historical/source coverage is marked and blocks unsafe correction, never invented. Ignore learning-origin sessions and their descendants. Do not add correction prompts to the user's source session or block its response on Jev.
- **Suggested Implementation:** Extend CLI with `retrospective ingest --harness opencode` and `retrospective drain`; plugin passes JSON through stdin to the packaged CLI, never interpolates transcript data into shell commands. Version-pin TypeScript plugin/SDK test dependencies in a small hooks package; fixtures reflect installed OpenCode 1.18.32 or a explicitly tested newer version. Normalize SDK versions in the adapter, not core. Native events stage bounded records to disk; terminal trigger launches a detached drain worker with single-host locking and persisted jobs, requiring no always-on daemon. Restart or later trigger resumes unfinished jobs, subject to global opt-out and request budgets. Use server task/session API to backfill and reconcile terminal snapshots; distinguish transport/tool-state errors from tool business failures/nonzero command exits. Capture relevant loaded-instruction paths and content hashes at use time where observable; never infer old content from today's file alone. Integrate plugin installation as an opt-in owned asset under global/project OpenCode plugin paths, with one global activation setting and scoped disable override. Include files in `scripts/release.sh` and `scripts/bootstrap.sh`, document setup/disable/status/recovery in `docs/runbooks/task-retrospective.md`, update README/AGENTS.md. Test npm/TS tooling only in the dedicated hooks package, not as a new mandatory dependency of the Go CLI.
