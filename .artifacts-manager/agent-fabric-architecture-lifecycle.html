Key Lifecycle Decisions

  • 1. Unified Interactive Discovery in Planner Unlike separate skill chains, Agent Fabric's primary Planner interrogates the user directly, grounds assumptions, and ingests project profiles before authoring the DAG.
  • 2. Two-Strike Design Reset After 2 substantive review rejections or QA failures, ordinary mutation stops. Expert Debugger must trace producer-to-consumer and name the invariant fix before mutation resumes.
  • 3. Human-Gated Release Gate Deployment is an irreversible, high-risk boundary. The system never deploys autonomously without explicit user confirmation, delegating post-approval to Deploy Supervisor.
  • 4. Context Firewalls Zero transcript forwarding between subagents. Every delegate receives an isolated brief with exact paths and returns structured machine-readable JSON.

Anti-Multi-Agent Trap

Google DeepMind research proved unstructured multi-agent meshes cause 17.2× error amplification. Agent Fabric uses strict centralized supervisor-worker DAGs with deterministic state machines.

Deploy Supervisor — Human Gate Protocol

Deployment constitutes an irreversible, high-risk side effect. The supervisor pauses execution before running external deployment pipelines. 

sequenceDiagram
    autonumber
    actor User as Human Operator
    participant PS as Plan Supervisor
    participant DS as Deploy Supervisor
    participant Live as Staging / Prod Target

    PS->>User: All code phases PASS. Ready for Release?
    alt User Rejects or Defers
        User-->>PS: Not now / Local tests only
        PS->>PS: Mark task completed (Local Merged)
    else User Confirms
        User->>DS: Authorize Deploy ($ deploy-supervisor)
        DS->>Live: Execute Deploy Pipeline (Pages / Cloudflare / K8s)
        DS->>Live: Run Smoke Test Endpoints
        DS->>Live: Check DB Migrations & Health Endpoint
        DS->>DS: Assert Version Tag & Commit SHA Parity
        DS->>DS: Generate RELEASE_EVIDENCE.md
        DS-->>User: Deployment PASS with concrete URLs & logs
    end
Gating Principle: Pre-merge verification proves code correctness locally; Deploy Supervisor proves production operational viability.

QA Runner — Conditional A11y Gate (WCAG 2.2)

Accessibility auditing is applied strictly to end-user UI surfaces. Backend, CLI, and library code evaluate to NOT_APPLICABLE. 

flowchart TD
    QA_START([QA Runner Dispatched]) --> CHECK_SURFACE{Touched files include\nEnd-User UI / Web DOM?}
    
    CHECK_SURFACE -->|NO: Backend, CLI, Library, API| SKIP_A11Y[A11y Status = NOT_APPLICABLE\nZero false blocker overhead]
    
    CHECK_SURFACE -->|YES: HTML, Svelte, React, Vue, CSS| RUN_A11Y[Execute A11y Audit\nWCAG 2.2 AA Criteria]
    
    RUN_A11Y --> A11Y_EVAL{Contrast, Labels, Roles,\nFocus & Keyboard valid?}
    
    A11Y_EVAL -->|PASS| A11Y_PASS[A11y Status = PASS\nAttach Axe / Lighthouse log]
    A11Y_EVAL -->|FAIL| A11Y_FAIL[A11y Status = FAIL\nAttach violated WCAG rule & selector]
    
    SKIP_A11Y --> FINAL_REPORT[Compile QA Evidence JSON]
    A11Y_PASS --> FINAL_REPORT
    A11Y_FAIL --> FINAL_REPORT
Pragmatic Invariant: UI features must respect screen readers, contrast, and keyboard navigation; backend services must not fail on irrelevant DOM criteria.
