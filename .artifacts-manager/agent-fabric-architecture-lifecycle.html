Proposed workflow

Keep planning and review. Hand the accepted plan once to the agent responsible for execution and delivery.

flowchart TD
P[Planner: HTML decisions and explained plan] --> R[Independent plan review]
R -- revise --> P
R -- pass --> H[Ops: publish once and reuse execution grant]
H -- one handoff --> I[Execution owner: code and tests]
I --> C[Independent code review]
C -- fix --> I
C -- accept --> V[Same owner: integrate and verify]

Cyan = one execution owner. That agent fixes failures, responds to review and delivers. A supervisor is optional when multiple independent workers genuinely need coordination.

Four concrete changes

1. Remove the default supervisor relay

Change Fabric's planner handoff and implementor delivery responsibility. The planner stays focused on human understanding; the execution owner handles code, tests, review fixes and integration.

Example: a dev-preview smoke test fails. The owner fixes it and reruns the affected check instead of returning the problem through a coordinating session.

2. Align the Ops hooks with existing authority

Update the decomposition overlay and adapter to consume one valid execution grant. Project children only when independently tracked phases are useful. Preserve publication readback and duplicate prevention.

Example: “Implement this approved dev plan” proceeds to work without another “Shall I start?” prompt. A plan-only request still stops at the plan.

3. Resume from one compact checkpoint

Keep the same owner, pending action, changed inputs and evidence links. Remove routine full-packet reconstruction and episode paperwork. Recheck evidence only when its inputs or requirements change.

Example: after a pause, resume the known atomicity fix rather than rebuilding eight input references and launching another review of unchanged material. Hard budgets still apply.

4. Keep hooks as adapters, not extra reviewers

Keep local checkpoint durability where needed; make secondary replication explicitly useful. Leave optional external pre-review outside the default route. Keep browser checks with the agent doing the work.

Example: an unavailable memory mirror does not delay a valid local result. This is already non-gating today; the change reduces default plumbing, not the verification bar.

What does not change

HTML questionnaires and explanations · free-text human decisions · browser validation · required tests · independent plan/code review for this MVP · explicit production confirmation · real permission and spending boundaries · no false PASS.

Fewer handoffs is the proposed improvement—not fewer checks or less human understanding. Genuine quota failures still require capacity or an authorized alternative.
