Agent Fabric Architecture & Extended Lifecycle

Reviewed workflows: independent acceptance, bounded recovery, continuation reuse, and scoped release verification.

Source: agents/*.md and docs/specs/agent-fabric.md. This view summarizes the contract; it is not a runtime orchestrator.

Direct execution intent supplies standing authority. Plan-only and report-only requests stop at their deliverables. A reviewed plan has one projection and dispatch owner.

Acceptance before execution

Two plan-review passes by default. A rejected or explicitly published candidate may be stored, but execution requires PASS on the current candidate and no blocking findings.

Self-locating handoffs

Packets declare roots, revision/worktree, scope, inputs, permitted paths, commands, DoD, evidence, rollback, and unresolved-locator behavior. Missing authority stops intake; ordinary setup remains operational work.

Independent, continued review

Initial reviewers are independent of authors. Later dispatches resume their own recorded sessions with refreshed packets and objective findings, never author transcripts or rationalizations.

Bounded recovery, never counter resets

Replacement DAGs require current plan-reviewer PASS before materialization or execution. The plan supervisor owns this two-pass review, including direct atomic handoffs; unresolved rejection returns terminal FAIL.

Budgets and ownership

Three normal mutations; attempts four and five require a materially distinct, in-scope reversible fix and new failing regression. Five is the absolute scope cap. Structural review occurs after diagnostics and before mutation four.

The loop supervisor owns atomic recovery. The plan supervisor materializes splits and integrates outputs. Replacement counters inherit attributable attempts; aggregate gates own no unique implementation work.

Checkpoint protocol

Loop: micro-ledger. Plan: macro-ledger. record-ledger loads before dispatch and records before dispatch / after return with expected_version. Reconcile in-flight work; stale writers reload.

Preserve scope, root, revision/worktree, next stage, sessions, counters, findings, evidence and blockers. No hook: explicit inline checkpoint. Installed persistence error: pause dispatch and recover.

Bug-fixer uses a separate handoff artifact; deploy-supervisor records release effects and child receipts in release evidence.

Release authority is scoped and durable

A release task names target, deployment DoD, rollback and traceable authority. Verify once; choose proportional safeguards without repeated prompts. Passing code phases alone never invents a release objective.

R -- restoration unverified --> F[FAILED]

F --> E

Static vs dynamic authority

Code reviewer owns types, static checks, security invariants and mental mutation checks. QA owns executed regression, runtime, persistence, payload and visual evidence. Missing dynamic evidence routes to QA, not another code rejection.

Conditional accessibility

End-user UI: WCAG 2.2 audit, including labels, contrast, focus and keyboard behavior. Backend, CLI, library and headless work: NOT_APPLICABLE. Prove new tests fail without the behavior when feasible.

Evidence and boundaries

Use actual tool-permitted evidence locators. Secrets stay in process memory. External capability, credentials, unresolved product intent and explicit policy/scope boundaries are verified blockers. Exhausted local repair is FAIL.

  • Role profiles: planner, worker, reviewer, supervisor, qa and solver. Models and tool syntax are adapter-owned.
  • Hooks enrich or validate authoritative inputs; they never repair a non-self-locating handoff by searching ambient state.
  • Exact-agent OpenCode overrides apply after profile mappings. Sync only touches the appropriate manifest-owned destinations.
  • Modified managed files are preserved unless force is explicitly selected. Generated files and manifest form a guarded write operation.
  • Canonical repetition across independently installed agents preserves complete role contracts. Within a role, each rule has one governing section.
